# УРОБОРОС — инструкции для Claude Code

## Статус проекта

Проект переосмысливается (v2). Прежний реализованный прототип и его ТЗ перенесены в `archive/` — это справочный материал для переиспользования отдельных сущностей, а не текущая основа. Новое ТЗ формируется постепенно в [`ТЗ.md`](ТЗ.md) (игровая механика/симуляция/экономика/фракции) и [`ТЗ_UI.md`](ТЗ_UI.md) (интерфейс игрока) в корне.

## Структура проекта

- `ТЗ.md` — новое техническое задание (механика/симуляция/экономика/фракции), наполняется по ходу обсуждения.
- `ТЗ_UI.md` — техническое задание по интерфейсу игрока (HUD, экраны, взаимодействия).
- `ТЗ_Ресурсы.md` — номенклатура сырья (17 видов), цепочки переделов (21 компонент I/II/III цикла), шахты, орбитальные станции и сборщики у аномалий. Два ресурса получаются с расходом других: металлический водород (газовые гиганты у центра) и антиматерия (чёрные дыры и нейтронные звёзды) — они заменили «экзотическую материю», а металлический заодно и «дейтерий» как топливо лучших двигателей.
- `ТЗ_Корабль.md` — классы кораблей (палубы/модули по классу), рецепты палубы/брони/19 модулей/8 типов оружия/уникальных построек Станции (Ускоритель/Портал/Луч смерти). Рецепты (в компонентах) заведены в `server/economy.go` (`shipItemCosts`) ради спроса на ресурсы — но постройка/бой/палубы как игровая механика по-прежнему чисто теория, в коде их нет (`server/ship.go` знает только один глобальный корабль без структуры), см. открытые вопросы в конце файла.
- `ТЗ_Экономика.md` — перенесённый внешний документ по экономике колонии: 4 шахты и 4 завода (без уровней у шахт, ТУ1–ТУ3 у заводов), рецепты и лимитирующие ресурсы производства по уровням, население/поселения (лимит по разнообразию пищи, рост/убыль ±1 в сутки), стоимость и содержание 20 типов зданий, эталонный расчёт «стандартной колонии». Число гексов в документе (41) расходится с реализованным (19/37/61 по размеру планеты, ТЗ_UI.md §5.1) — см. примечание в шапке файла.
- `server/` — Go-сервер v2: единые часы игрового времени, авторитетная симуляция сектора, раздача `client/` (в том числе на телефон по локальной сети). Подробности и API — в [`server/README.md`](server/README.md).
  - `server/clock.go` — единое время: `months += speed × Δt`, ускорение меняет только множитель.
  - `server/galaxy.go` — генератор (зоны, рукава, массы, кривая скорости по орбитам), перенесён из клиента.
  - `server/sim.go` — жизненный цикл объектов: очередь выходов, оборот с возвратом массы, события.
  - `server/planets.go` — заселение звёзд планетами, распространение ресурсов/среды, гекс-карта поверхности радиуса 2/3/4 по размеру планеты (`generateSurface`) и распределение ресурсов по гексам (`distributeHexResources` — фон+месторождения для металлов/газов, привязка к биому для воды/биогенных), ТЗ.md §2.5. 16-й ресурс — металлический водород (`resourceDefs`, ТЗ_Ресурсы.md §3.1): только газовые гиганты, только зоны 1–4 (резкий позиционный гейт `metalHydrogenMaxR`, не пологий galMod), только у синих гигантов/нейтронных звёзд (starType) — редкость подобрана эмпирически так, чтобы запас/спрос был ниже, чем у битумов.
  - `server/ship.go` — корабль игрока: один глобальный объект на сервере (пока нет аккаунтов), реальное время полёта (не игровые месяцы), навигация/посадка/взлёт (ТЗ.md §2.7.1). Посадка на газовые гиганты отклоняется — твёрдой поверхности нет.
  - `server/buildings.go` — здания и транспортная сеть колонии (ТЗ_UI.md §5.3, ТЗ_Экономика.md §§12/15): модель `Building`, связность гексов (`connectedHexes`, BFS от домашнего гекса), стартовая колонизация 4 столичных планет (`bootstrapColony` — шахты на богатейшие гексы, транспортные узлы мостят разрывы). Фаза 1 (только размещение/связность) — без посуточной добычи/производства, это фаза 2; население — исключение, `computePopulation` заселяет колонию один раз при бутстрапе по лимиту разнообразия пищи (ТЗ_Экономика.md §11.2: число Жилых модулей × 5/7/9 в зависимости от того, сколько из 3 типов пищи колония способна производить по составу зданий — не по смоделированному запасу склада, которого не существует; стандартная колония производит все 3 → 10×9=90). Посуточный рост/убыль ±1 (§11.2) не симулируется — значение статично с момента заселения.
  - `server/economy.go` — данные для админ-панели `client/economy.html`: цена/масса 16 реализованных ресурсов (редактируются администратором, персистентны в `economy_data.json` рядом с сервером — источник истины между перезапусками), рекомендованная цена — от РЕАЛЬНОГО запаса ресурса в текущем сгенерированном секторе (`recommendedPriceFromTotals`, `5 × макс.запас/запас_ресурса`, кратно 5), не от статичного коэффициента. Рецепты 21 компонента (I/II/III цикл), стоимость постройки 19 зданий и корабль (`shipItemCosts` — каркас/броня/19 модулей/8 типов оружия/4 уникальные постройки Станции-Дредноута, ТЗ_Корабль.md) — временные справочные данные, не редактируются; итог пересчитывается резолвером (`resolveComponent`/`resolveBuilding`/`resolveShipItem`) от текущих цены/массы. `shipItemCost.Multiplier` — явная ценовая надбавка поверх рецепта (не трогает массу/спрос); телепорт-модуль — единственный расчёт по формуле (`buildTeleportItem`, цена всегда ×5 от средней цены модулей, живой пересчёт). Только антиматерия не реализована в симуляции — не входит в список ресурсов, встречается как вход в рецепты с флагом `Incomplete`. Металлический водород реализован (§16-й ресурс, planets.go) — обычный вход в рецептах.
  - Запуск: `cd server && go run .` — адрес для телефона печатается при старте.
- `client/` — новый прототип v2 (HTML/JS, mobile-first):
  - `client/world.js` — **единый источник данных о мире для всех экранов** (ТЗ_UI.md §1.0): справочники, часы игрового времени, состояние (корабль + сектор) с общим опросом, положения тел как чистые функции времени, действия корабля, масштабы. Экраны отсюда только читают и рисуют — считать положение тел или ходить в API за состоянием мира самим им нельзя, иначе радар, карта и навигация разъезжаются.
  - `client/ship.html` — HUD масштаба «Корабль» (ТЗ_UI.md §2): мир рисуется в масштабе 1:1 (1 клеть = ширина экрана), радар и список объектов — настоящие. Меню трёх кнопок (Бой/Полёт/Действия), боковые регуляторы и сам спрайт корабля — по-прежнему заглушки.
  - `client/galaxy.html` — карта масштаба «Доступная галактика» (ТЗ_UI.md §3). **Требует запущенного сервера** — сам ничего не генерирует и не разыгрывает: берёт состав сектора и время из API, а позиции считает по формуле `x = x0 + arc·(t − t0)`. Открытая как `file://`, покажет плашку «нет связи с сервером». Кнопка «лететь» прокладывает настоящий курс кораблю, на карте виден его маркер.
  - `client/system.html` — карта масштаба «Звёздная система» (ТЗ_UI.md §4): система, в которой сейчас находится корабль, навигация к звезде/планетам внутри неё. Посадка проигрывает анимацию (корабль летит к центру планеты и уменьшается, 3–5 с) и ведёт на `planet.html`.
  - `client/planet.html` — экран масштаба «Планета» (ТЗ_UI.md §5): гекс-карта поверхности (радиус 2/3/4 по размеру планеты, данные с сервера, `Planet.Surface`), фоновый слой-заглушка под текстуры, 7 точек застройки на гекс (закрашены по числу настоящих зданий), пунктирное кольцо — транспортный узел, тусклый гекс с красной обводкой — изолирован от сети. Панель сведений о гексе (тип/ресурсы/население/строения — ресурсы и строения настоящие; население планеты — реальное с сервера, `computePopulation`, но по гексам не разбито, это по-прежнему теория) и панель строений под картой — тоже настоящие данные. 8 кнопок разделов сверху/снизу — заглушки-тосты, кроме **СКЛАД** (по образцу `archive/docs/TZWarehouse.md`, UI без бэкенда — накопленного запаса на сервере нет, фаза 2): подменяет `#map-outer` на месте (не оверлей на весь экран, как было в архиве — меню остаётся кликабельным), 3 вкладки (Ресурсы/Аренда-заглушка/Перегрузка-заглушка), цены/масса — из живого `/api/economy`, состояние сессии (`whState`, сброс при перезагрузке), **СТРОИТЕЛЬСТВО** (по образцу `archive/server/ui/development.js`, тот же уровень готовности): список 19 типов зданий с числом уже построенных (реальные `currentPlanet.buildings`), сводка населения/энергии сверху — честно посчитана из формул `ТЗ_Экономика.md` §11.2/§12.1/§12.2 (10 мест/Жилой модуль, население — реальное с сервера (`Planet.Population`), прирост/сутки всегда 0 — посуточный рост/убыль ±1 не симулируется, это статичное значение заселения, 1 энергия потребления/здание любого типа, +10/+5 от генератора/панели, отдельно энергия на 4 добывающих типа), клик по зданию открывает модалку (стоимость из `/api/economy`, «сколько на складе» из `whState` — всегда 0/N, компоненты не хранятся) с описанием эффекта и кнопками Построить(заглушка)/Закрыть, и **ВЕРФЬ**/КОСМОДРОМ (ТЗ_Корабль.md, тот же уровень готовности — UI полностью рабочий, но `server/ship.go` о палубах/модулях не знает, «Построить» открывает только список ресурсов): выбор класса (6 военных + 6 гражданских вариантов из 7, ТЗ_Корабль.md §1 — Станция/Ковчег исключены: строятся только в открытом космосе, не на планетарной Верфи, максимум для планеты — Дредноут/Танкер), сетка палуб (силуэт по присланному пользователем эскизу, не √decks-квадрат — своя форма на каждое встречающееся число палуб: 1/2/4/5/10/21 клеток, `SHIP_DECK_SHAPES`; Станция/Ковчег (60 палуб) — отдельно, крест из 5 блоков 4×3=12, центральный блок — «ядро» с золотой обводкой, где вместо обычных модулей ставятся 4 уникальные постройки Станции — Ускоритель/Портал/Антигравитатор/Луч смерти — или любое из 19 зданий колонии, ТЗ_Корабль.md §7; клик выбирает палубу, показывает занятость слотов и прочность палубы = 3 + Σ модулей), панель характеристик (прочность/грузоподъёмность/масса — настоящий расчёт из `/api/economy`; ускорение/огневая мощь/длительность полёта/дальность прыжка — помечены `*`, условные оценки, формул для них в ТЗ нет), 4 слота модулей текущей палубы (лишние сверх `perDeck` класса — перечёркнуты), клик по слоту открывает карусель из 19 модулей по 2 за раз (`‹`/`›`), заблокированных без нужного здания (Верфь — для любых, дополнительно Завод улучшенных компонентов — для 6 «продвинутых» модулей типа оружия/авионики, проверка теми же реальными `currentPlanet.buildings`, что и в СТРОИТЕЛЬСТВО), установка модуля автоматически переводит на первую ещё не полностью занятую палубу. Конфигурация класса — в `localStorage` (кнопки Сохранить/Загрузить осмысленны только с персистентностью), Сбросить — очищает модули текущего класса, Строить — сворачивает установленные модули+каркас палуб в список базовых ресурсов через `baseTotals`. Точки застройки и кнопка ремонта — по-прежнему заглушки, рабочая только «Взлёт». Единственный вход в планету — посадка (`ship.landed`); переходы с галактической карты/HUD корабля на флот, уже находящийся на планете, тоже сюда ведут.
  - `client/planets.html` — админ-инструмент: плоский список всех планет сектора (ТЗ_UI.md §3.6), открывается кнопкой из админ-панели. Сводная статистика по ресурсам (сумма/цена/масса) переехала в `economy.html`.

Сводка (табл. 5) — спрос ×`COLONY_COUNT` (12 колоний, не одна демонстрационная), плюс сжигание водорода (1/10 произведённых компонентов + 1/выработку гекса на добычу) и население+питание (1 житель/здание + 1 экипаж/СЖО, 1 ед.пищи/житель/сутки через Биосинтетику) — оба добавлены в спрос строк соответствующих ресурсов, не только отдельным блоком. Число модулей на палубу зависит от класса (по общему числу занятых палуб, `SHIP_CLASS_TABLE` — та же таблица, что `SHIP_CLASSES` в `planet.html`, только Крейсер/Баржа/Линкор/Лайнер/Дредноут/Танкер подняты до 6/12/22 палуб). Кнопка «Настроить модули» открывает таблицу с живыми ценой/массой из `/api/economy`, панелью масса/прочность/энергетика (последняя — условная оценка, в ТЗ её нет) и списком готовых компонентов ТУ1-3 сборки (не сырья). Под каждой схемой — сводка по секторам (ПП/ОМ/ЗП). Кнопка «+ ДОБАВИТЬ КОРАБЛЬ» — библиотека не ограничена стартовыми 20. Автосохранение в `localStorage` на каждое действие (плюс восстановление при загрузке) и кнопка «Экспорт JSON» — единственный способ передать конфигурацию между браузерами/устройствами, импорта нет (по решению пользователя — «одного файла и одной версии достаточно»).

## Архитектура v2

Симуляция — на сервере, клиент только отображает. Разыгрывать что-либо на клиенте нельзя: два устройства должны видеть одну и ту же галактику. Всё игровое время идёт от сервера; ускорение для тестов — серверный множитель (месяцев в реальную секунду), а не локальная настройка браузера.
