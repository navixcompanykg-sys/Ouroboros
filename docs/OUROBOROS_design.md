## 1. СТРУКТУРА ПРОЕКТА

```
server/
├── galaxy_gen.go       # Генератор галактики (Go). Тег //go:build ignore — не компилируется с main.go.
│                       # Запуск: go run galaxy_gen.go -config config.json
├── galaxy.json         # Результат генерации. Читается браузером при старте.
├── galaxy.html         # Весь фронтенд: симуляция, физика, рендер, UI. Не требует сборки.
├── config.html         # Браузерный редактор config.json. Открывается кнопкой ⚙.
├── config.json         # Параметры симуляции. Загружается при старте galaxy.html.
├── registry.html       # Просмотр реестра звёзд. Открывается кнопкой REGISTRY.
├── star_registry.json  # Постоянный файл реестра (создаётся при рождении первой звезды).
├── main.go             # Go HTTP сервер. Порт 8080. Все API-эндпоинты и раздача файлов.
├── go.mod
└── serve.bat           # Быстрый запуск на Windows.
```

### Назначение файлов

**galaxy_gen.go** — генерирует `galaxy.json` по параметрам из `config.json`. Поддерживает флаг `-seed N`. Содержит захардкоженную константу `V_FLAT = 1.3963` для расчёта начальных скоростей — должна совпадать с `config.json`.

**galaxy.html** — единый фронтенд. Загружает `galaxy.json`, запускает тики симуляции, рендерит Canvas. Никакой сборки не требует. Вся логика физики, столкновений, температуры и жизненного цикла объектов находится здесь в JavaScript.

**config.html** — браузерный редактор параметров. При загрузке читает дефолты из `getDefaults()` в своём JS, затем накладывает значения с сервера через `deepMerge`. При сохранении делает `POST /config`. Кнопка «Reset Defaults» возвращает значения из `getDefaults()`.

**⚠ ПРАВИЛО СИНХРОНИЗАЦИИ ТРЁХ ФАЙЛОВ:**

При изменении любой константы симуляции её нужно обновить во **всех трёх местах** одновременно:

| Файл | Где менять |
|---|---|
| `galaxy.html` | Блок `let CFG = {...}` и соответствующая строка в `loadConfig()` |
| `config.json` | Соответствующий ключ в нужной секции |
| `config.html` | Функция `getDefaults()` и подпись `default: ...` у поля формы |

Если обновить только `config.json` но не `getDefaults()` в `config.html` — кнопка «Reset Defaults» восстановит старые значения. Если обновить только `CFG` в `galaxy.html` но не `config.json` — значения сбросятся при перезапуске сервера.

**galaxy_gen.go** — помечен тегом `//go:build ignore` (первая строка файла). Это стандартный Go-паттерн для standalone-инструментов в том же пакете: файл исключается из обычной сборки, но доступен через `go run galaxy_gen.go`. Без тега возникает ошибка `main redeclared` при сборке `main.go`.

**registry.html** — просмотр реестра звёзд. Подключается к серверу через SSE (`EventSource('/registry/stream')`). Дельта-рендеринг: рождения через `appendChild`, смерти через точечное обновление ячеек `[data-field]`. Статистика вычисляется клиентски.

**main.go** — эндпоинты:
- `GET /` → отдаёт `galaxy.html`
- `GET /config` → читает и возвращает `config.json`
- `POST /config` → записывает новый `config.json`
- `POST /generate?seed=N` → запускает `go run galaxy_gen.go`, возвращает новый `galaxy.json`
- `GET /registry` → возвращает `star_registry.json` целиком
- `GET /registry/stream` → SSE-поток событий (`init / birth / death / reset`)
- `GET /registry/stats` → статистика реестра (O(n), один проход по файлу)
- `POST /registry/birth` → append новой записи о рождении звезды
- `POST /registry/death` → patch записи по `star_id` при смерти
- `POST /registry/reset` → очищает реестр (записывает `[]`)

Тип объекта определяется его суммарной массой:

| Объект | Масса (у.е.) |
|---|---|
| Туманность | 1–2 |
| Астероидное поле | 3–30 |
| Формация | ≥ 31 (нет верхнего предела) |
| Красный карлик | 51–300 |
| Жёлтый карлик | 301–600 |
| Синий гигант | 601–1000 |
| Нейтронная звезда | наследуется (не определяется массой) |

**Примечание о формации:** формация — обязательная промежуточная стадия перед любой звездой. Объект с массой ≥ 31 при **динамическом создании** (разлёт, слияние облаков) всегда становится формацией, а не звездой напрямую. Звезда рождается только через `FORMATION_TICKS (6)` тиков в `checkFormationBirth`. Порог ≥ 51 — условный минимум для рождения звезды, а не граница мгновенного превращения.

**Примечание о белом карлике:** белый карлик рождается исключительно при остывании звезды (T ≤ 10) с остатком массы 10–15. Из формаций и слияний белый карлик не возникает.

### Прозрачность и тепловая окраска

Яркость объекта зависит от его массы в своём диапазоне:

```
alpha = 0.35 + 0.65 × clamp((mass - lo) / (hi - lo), 0, 1)
```

Чем тяжелее объект в своём диапазоне, тем ярче он отображается.

Горячие звёзды смещаются в белый/оранжевый: `tint = floor(temp / COLLAPSE_LIMIT × 180)`. R увеличивается, G и B уменьшаются пропорционально tint.

## 4. ФИЗИКА

### 4.1 Плоская кривая вращения

Вместо классической гравитации `F = G*M/r²` для центра используется **плоская кривая вращения** — как в реальных галактиках с тёмной материей:

- **Единая орбитальная скорость `V_FLAT = 1.3963 у.е./тик`** для всех объектов на любом радиусе
- Орбитальный период растёт линейно с радиусом: `T = 2π × r / V_FLAT`

| r (у.е.) | Период (тиков) |
|---|---|
| 5 | ~22 |
| 10 | ~45 |
| 20 | ~90 |
| 40 | ~180 |
| 60 | ~270 |
| 80 | ~360 |

Это означает: объект на орбите r=80 совершает один оборот за 360 тиков, а на r=5 — примерно за 22 тика. Центральное ускорение для удержания на круговой орбите со скоростью V_FLAT вычисляется как `a = V_FLAT² / r`.

### 4.2 Интегратор движения (Leapfrog)

Используется симплектический интегратор второго порядка (Leapfrog / Verlet со сдвигом), который сохраняет энергию лучше, чем метод Эйлера:

```
[ax, ay] = computeAccelXY(o)

// Half-kick
vx += ax × 0.5
vy += ay × 0.5

// Drift
x += vx
y += vy

// Second half-kick
vx += ax × 0.5
vy += ay × 0.5
```

### 4.3 Гравитация в computeAccelXY

Debris-объекты (флаг `debris=true`) пропускаются — не получают никакого ускорения.

Для всех остальных объектов два источника ускорения:

**1. Центральное притяжение (все не-debris объекты):**

Центростремительное ускорение для поддержания плоской кривой вращения:

```
cdx = CENTER - o.x
cdy = CENTER - o.y
cd = sqrt(cdx² + cdy²) + 0.001        // дистанция до центра
centripetal = V_FLAT² / cd
ax += centripetal × (cdx / cd)
ay += centripetal × (cdy / cd)
```

Это обеспечивает круговые орбиты с постоянной скоростью V_FLAT на любом радиусе.

**2. Гравитация от массивных объектов — через предвычисленную таблицу:**

Массивными считаются: синие гиганты, жёлтые карлики с mass ≥ 500, чёрные дыры.

```
GRAVITY_TABLE[r] = K_BASE / r^POWER    для r = 1..20
K_BASE = 0.00002
POWER  = 1.5

a = GRAVITY_TABLE[round(d)] × mass_источника
```

Таблица предвычисляется один раз при старте. В рантайме нет делений — только табличный lookup. Радиус влияния: **20 у.е.** — жёсткий обрыв, дальше сила равна нулю.

### 4.4 Orbital drag (стабилизация орбит)

Применяется каждый тик для всех не-debris объектов, находящихся за пределами зоны хаоса (r > CHAOS_R).

**Тангенциальный drag** — тянет тангенциальную скорость к V_FLAT:

```
sinT = sin(θ)
cosT = cos(θ)
v_tang = -vx × sinT + vy × cosT          // тангенциальная скорость
excess = v_tang - rotDir × V_FLAT        // отклонение от идеальной орбиты
massFactor = min(2.0, mass / 300.0)      // нормировка: тяжёлые объекты стабилизируются сильнее
drift = -excess × ORBITAL_DRAG × massFactor
x += cosT × drift
y += sinT × drift
```

`ORBITAL_DRAG = 0.05`

**Радиальный drag** — гасит радиальную компоненту скорости, помогает захвату влетающих объектов на орбиту:

```
θ = atan2(y - CENTER, x - CENTER)
cosT = cos(θ)
sinT = sin(θ)
v_rad = vx × cosT + vy × sinT           // радиальная скорость (+ наружу, − внутрь)
v_rad_new = v_rad × (1 − RADIAL_DAMP)   // затухание
dv = v_rad_new − v_rad
vx += dv × cosT
vy += dv × sinT
```

`RADIAL_DAMP = 0.12`

**Эффект радиального drag:** объект, влетающий со скоростью 1.0 у.е./тик к центру, теряет 50% радиальной скорости за ~6 тиков, 90% за ~18 тиков. Это достаточно для захвата на орбиту до достижения зоны хаоса.

### 4.5 Флаг Debris

- `debris = true` → объект не получает гравитацию и не подвергается orbital drag
- `debris_ticks` — счётчик, уменьшается на 1 каждый тик
- При `debris_ticks ≤ 0` флаг `debris` снимается, объект начинает нормально взаимодействовать с физикой
- Дебрисами становятся: осколки взрывов (60% масса) и все влетающие объекты из пула возврата
- Стандартное значение: `debris_ticks = 10`

Буфер края галактики ~20 у.е. При скорости влёта 1 у.е./тик за 10 тиков объект проходит ~10 у.е. и входит в галактику, после чего начинает работать гравитация.

### 4.6 Начальные скорости при генерации (galaxy_gen.go)

Плоская кривая вращения — одинаковая скорость для всех орбит:

```
vx = -rotDir × V_FLAT × sin(θ)
vy =  rotDir × V_FLAT × cos(θ)
```

Направление вращения (`rotDir = +1` или `−1`) определяется первым броском RNG от сида галактики.

### 4.7 Граничные условия

- `r < CHAOS_R (2 у.е.)` → объект поглощается, его масса добавляется в пул возврата
- `x < −2` или `x > FIELD_SIZE + 2` или аналогично по Y → объект поглощается, масса в пул возврата

### 4.8 Генерация — спиральные лучи

- 40 лучей с шагом `π / 20` радиан (равномерно по 360°)
- Каждый луч разбит на 10 колец от CHAOS_R до GALAXY_R
- Число звёзд на луч по кольцам: `[1, 2, 3, 4, 5, 7, 9, 8, 6, 5]`
- До 40 попыток размещения каждой звезды с проверкой MIN_DIST
- Недостающие звёзды добираются случайным размещением `randInGalaxy`

### 4.10 Массовый дрифт к центру (динамическое трение)

Каждый тик для всех **не-облаков** (звёзды, ЧД, формации) применяется прямая позиционная коррекция — объект смещается к центру на величину:

```
dr = DRIFT_K × mass / r    (у.е. за тик)
```

**Важно: дрифт применяется как прямое смещение позиции, а не через скорость.** Это принципиально — если добавлять дрифт как ускорение в leapfrog, то `RADIAL_DAMP` (12%/тик) гасит накопленную радиальную скорость и съедает ~72% дрифта за 10 тиков. Прямая коррекция позиции применяется после всей физики и radial drag и не подвергается гашению.

**Физический смысл:** аналог динамического трения Чандрасекара — массивный объект тормозится о звёздный фон, теряет угловой момент и медленно спирально падает к центру. Чем тяжелее объект, тем быстрее он мигрирует внутрь.

**Калибровка:** объект с mass=500 на орбите r=50 у.е. смещается на **5 у.е. к центру за один полный орбитальный период** (~225 тиков).

**Формула Δr за один период** (T = 2π×r / V_FLAT):

```
Δr = DRIFT_K × mass / r × T = DRIFT_K × mass × 2π / V_FLAT
```

Δr **не зависит от r** — каждый объект падает на одинаковое расстояние за один свой орбитальный период, независимо от того, где он находится. Это следствие того что T ∝ r и dr ∝ 1/r: они компенсируют друг друга.

Δr растёт **линейно с r** за фиксированное число тиков — объект на краю (r=80) в любой момент времени смещается быстрее чем на r=40, но за один свой полный оборот падает на то же расстояние.

**Таблица Δr за один орбитальный период:**

| Объект | Mass | r=20 у.е. | r=50 у.е. | r=80 у.е. |
|---|---|---|---|---|
| Красный карлик | 150 | 0.47 у.е. | 1.5 у.е. | 2.4 у.е. |
| Жёлтый карлик | 400 | 1.27 у.е. | 4.0 у.е. | 6.4 у.е. |
| Жёлтый (калибровка) | 500 | 1.58 у.е. | **5.0 у.е.** | 8.0 у.е. |
| Синий гигант | 700 | 2.2 у.е. | 7.0 у.е. | 11.2 у.е. |
| ЧД (стартовая) | 1500 | 4.7 у.е. | 15 у.е. | 24 у.е. |
| ЧД (крупная) | 5000 | 15.8 у.е. | 50 у.е. | 80 у.е. |

Туманности и астероиды в расчёт не включаются — их масса мизерна, вычислительная нагрузка не оправдана. Дрифт применяется только к звёздам, ЧД и формациям.

`DRIFT_K = 2e-5`

## 5. ПОРЯДОК ШАГОВ В ОДНОМ ТИКЕ

```
1. processReturnPool    — влёт новых объектов из пула возврата
2. leapfrogStep         — физика движения (гравитация, orbital drag, radial drag, дрифт)
3. checkBoundaries      — поглощение в зоне хаоса и за полем
4. applyTemperature     — изменение температуры звёзд на dT/тик
5. applyBHRadiation     — потеря массы ЧД, нагрев соседних звёзд
6. processStarLifecycle — смерть звёзд от остывания или перегрева
7. processUnstable      — взрыв «больших событий» (тик задержки уже прошёл)
8. detectAndResolve     — детектирование и разрешение столкновений
9. processFormations    — рождение звёзд из формаций
10. updateDOM + draw    — обновление статистики и рендер канваса
```

`fastTick()` выполняет шаги 1–9 без рендера. Используется при Jump to Tick — блоками по 50 тиков через `requestAnimationFrame`, не блокирует UI.

### Порядок операций внутри leapfrogStep

Порядок внутри шага 2 критичен — нарушение меняет физику:

```
1. Half-kick:       vx += ax×0.5,  vy += ay×0.5
2. Drift:           x  += vx,      y  += vy
3. Orbital drag:    тянет v_tang → V_FLAT (через позицию)
4. Radial drag:     гасит v_rad на RADIAL_DAMP (через скорость)
5. Second half-kick: vx += ax×0.5,  vy += ay×0.5
6. Массовый дрифт:  прямая коррекция позиции dr = DRIFT_K×mass/r к центру
```

Массовый дрифт (шаг 6) применяется **последним** — после radial drag и second half-kick. Это принципиально: если применять дрифт как ускорение (шаги 1/5), то radial drag гасит накопленную радиальную скорость и уничтожает ~72% эффекта за 10 тиков. Прямая коррекция позиции обходит это полностью.

## 6. ДЕТЕКТИРОВАНИЕ СТОЛКНОВЕНИЙ

Пространственная сетка O(n) каждый тик. Ячейка сетки = `MIN_DIST`.

- Расстояние между объектами < **0.9 у.е.** → столкновение
- Каждая пара обрабатывается максимум один раз (множество `seen`)
- Пары с уже умирающими объектами в текущем тике пропускаются

### Смена типа облака при росте массы

При поглощении одного облака другим суммарная масса может превысить порог типа. В этом случае поглотитель меняет тип (`typeFromMass`):

- Туманность (1–2) + любое облако → если масса ≥ 3 → становится **астероидом**
- **Астероид + астероид** → постепенная передача **10 ед. массы / тик** от меньшего к большему; меньший удаляется только когда масса достигает 0; при превышении порога 31 у.е. поглотитель становится формацией
- **Астероид + звезда** → **5 ед./тик** от астероида к звезде; астероид продолжает движение, исчезает при массе = 0
- **Астероид + формация** → мгновенное полное поглощение (100%) через прямое столкновение (0.9 у.е.)
- Астероид (3–30) + облако (не астероид) → если масса ≥ 31 → становится **формацией** (получает `formation_tick`)
- Формация (≥ 31) + облако → если масса ≥ 1001 → становится **чёрной дырой**

**Важно:** облако с массой ≥ 51 при поглощении становится формацией, а не звездой. Звезда рождается только через 6 тиков в `checkFormationBirth`.

### Счётчики столкновений

| Пара | Счётчик |
|---|---|
| Cloud × Cloud | colCC |
| Cloud × Star | colCS |
| Star × Star | colSS |
| Star × BH | colSB |
| BH × BH | colBB |
| Cloud × BH | colCB |

## 7. ТЕМПЕРАТУРНАЯ СИСТЕМА

### 7.1 Принципы

- `T ≥ 1000` → коллапс (взрыв / сверхновая)
- `T ≤ 10` → смерть от остывания (для всех типов кроме синего гиганта, который нагревается)

### 7.2 dT/тик — изменение температуры каждый тик

| Тип | Стартовая T | dT/тик | Жизнь без нагрева (тиков) |
|---|---|---|---|
| Красный карлик | 100 | −0.2 | ~450 |
| Жёлтый карлик | 250 | −1.0 | ~240 |
| Синий гигант | 150 | +4.7 | ~178 (перегрев) |
| Нейтронная звезда | 500 | −0.34 | ~1441 |
| Белый карлик | 50 | −0.05 | ~800 |

Синий гигант постоянно нагревается и неизбежно взрывается. Остальные типы медленно остывают. Жёлтый карлик остывает быстрее нейтронной звезды и чаще даёт белых карликов при небольшой начальной массе.

### 7.3 Потеря массы звёздами

**Отключена.** Все коэффициенты DM равны нулю. Секция mass_loss в конфиге — исторический артефакт.

### 7.4 Температура при столкновении

**Звезда + звезда:** взвешенное среднее по массам:
```
T_new = (T1 × M1 + T2 × M2) / (M1 + M2)
```

**Звезда + облако:** изменение температуры звезды зависит от типа облака:

```
Туманность:  T_new = max(0,    T_star − mass × NEB_COOLING_PER_MASS)   // охлаждает
Астероид:    T_new = min(1000, T_star + mass × AST_TEMP_PER_MASS)       // нагревает
Формация:    T_new = min(1000, T_star + mass × AST_TEMP_PER_MASS)       // нагревает как астероид
```

Постепенное всасывание туманности (`drainNebulae`, 1 ед./тик): охлаждает звезду на `NEB_COOLING_PER_MASS` за каждую всосанную единицу массы.

Коэффициент kv (от скорости столкновения) **упразднён** — температура не зависит от скорости.

### 7.5 Тепловые коэффициенты облаков

| Тип | ΔT на у.е. массы | Направление |
|---|---|---|
| Туманность | −3 (`NEB_COOLING_PER_MASS`) | Охлаждает звезду |
| Астероид | +1 (`AST_TEMP_PER_MASS`) | Нагревает звезду |
| Формация | +1 (`AST_TEMP_PER_MASS`) | Нагревает как астероид |

## 8. ПРАВИЛО РАСПАДА — ДВА РЕЖИМА

Существует два принципиально разных режима в зависимости от причины события.

---

### Режим 1 — Дисперсия (перегрев / остывание / переполнение)

Применяется при:
- Перегрев звезды (T ≥ 1000)
- Остывание звезды (T ≤ 10)
- Распад НЗ (mass ≥ 1001)

**Результат:**
- **60% массы** → осколки через `ejectSixty`: 12 направлений по 30°, **2 осколка на направление** = **24 осколка итого**. Первый: смещение **0.5–1 у.е.**, скорость **1–2 у.е./тик**. Второй (та же ось): смещение **1.1–1.5 у.е.**, скорость **2–3 у.е./тик**. `debris=true`, `debris_ticks=5`
- **40% массы** → остаток через `makeByMass`, тип зависит от источника

**Тип остатка (40%) по источнику:**

| Источник | Остаток | Примечание |
|---|---|---|
| Синий гигант (перегрев) | ЧД или НЗ (чередование) | remnant_nova — см. §10 |
| Жёлтый карлик (перегрев) | Формация с V_FLAT | ejecta |
| Красный карлик (перегрев) | Формация с V_FLAT | ejecta |
| НЗ (mass ≥ 1001) | Формация с V_FLAT | ejecta |
| Любая звезда (остывание) | Белый карлик (10–15) / формация / астероид / туманность | remnant_decay |

**Тип осколка (60%) по его массовой доле:**

| Масса осколка | Тип |
|---|---|
| 1–2 | Туманность |
| 3–30 | Астероид |
| 31+ | Формация (скорость импульса разлёта, звезда рождается через 6 тиков) |

Верхний предел массы осколка не ограничен — даже осколок с массой 200+ становится формацией, а не звездой напрямую.

**Важно:** формация-осколок получает скорость разлёта (`IMPULSE_MIN`), а **не** V_FLAT. На неё действует `debris=true` (5 тиков без гравитации и orbital drag), после чего orbital drag постепенно выравнивает орбиту. Немедленная подмена на V_FLAT создаёт артефакт — идеальный круг из формаций сразу после взрыва.

**Скорость при взрыве (explode):** осколки разлетаются с нуля. Остаток получает круговую скорость V_FLAT:
```
theta  = atan2(y - CENTER, x - CENTER)
vx_rem = -rotDir × V_FLAT × sin(theta)
vy_rem =  rotDir × V_FLAT × cos(theta)
```

**Скорость при остывании (decay):** скорость источника сохраняется — звезда «рассыпается» в движении.

**Большие события (mass ≥ BIG_EVENT_MASS = 601)** при перегреве: объект получает `unstable = true` в текущем тике (визуальный пульс), взрывается в следующем тике через `processUnstable`. Это solo-взрыв — партнёра нет. Облака поглощаются звездой напрямую, без unstable.

---

### Режим 2 — Слияние (столкновение двух звёзд)

Применяется при столкновении звезда+звезда.

**Важнейшее правило: синий гигант НЕ участвует в слиянии.**

Если хотя бы одна из двух звёзд является синим гигантом — применяется Режим 1 (дисперсия), остаток = ЧД или НЗ. Физический смысл: синий гигант достаточно массивен чтобы при коллапсе образовать компактный объект, а не звёздные ясли. Если бы синий гигант оставлял формацию — НЗ и ЧД никогда бы не рождались через столкновения, что разрушает баланс.

Для всех остальных пар (красный+красный, красный+жёлтый, жёлтый+жёлтый, НЗ+любая кроме синего):

- **40% суммарной массы** → осколки через `ejectSixty` (те же параметры)
- **60% суммарной массы** → формация в центре масс пары, скорость V_FLAT, `formation_tick = tick`

Формация сразу начинает аккрецировать окрестные облака и через 6 тиков рожает звезду по итоговой накопленной массе. Путь к синим гигантам через слияния:

| Столкновение | Формация (60%) | Итог через 6 тиков |
|---|---|---|
| Красный (150) + красный (150) | 180 у.е. | Красный карлик |
| Жёлтый (400) + красный (200) | 360 у.е. | Жёлтый карлик |
| Жёлтый (500) + жёлтый (500) | 600 у.е. | **Синий гигант** |

---

### Обычные столкновения (облако + облако, звезда + облако)
## 9. ЖИЗНЕННЫЙ ЦИКЛ ЗВЁЗД

### Пороги смены типа

| Переход | Порог массы |
|---|---|
| → Красный карлик | ≥ 101 |
| → Жёлтый карлик | ≥ 301 |
| → Синий гигант | ≥ 601 |

Деградация невозможна (масса не уменьшается у звёзд). Эволюция фиксируется счётчиками `evRY` (Red→Yellow) и `evYB` (Yellow→Blue). При смене типа `age` копируется в новый объект.

### Поглощение облака звездой

- Если тип **не изменился** → мутация на месте: обновляются `mass, temp, x, y, vx, vy, r, theta, omega`. **`id` и `age` сохраняются.**
- Если тип **изменился** → создаётся новый объект через `makeObject`, `age` копируется из старого

### Смерть от остывания (T ≤ 10)

Все типы кроме синего гиганта. Правило 60/40, режим `decay` + `remnant_decay`.

Остаток `remnant_decay` по массе:
- 10–15 → белый карлик
- >15 → формация с V_FLAT
- 3–9 → астероид
- <3 → туманность

### Смерть от перегрева (T ≥ 1000)

Все типы. Правило 60/40, режим `explode`. Остаток: `remnant_nova` для синего гиганта, `ejecta` для остальных. Остаток получает V_FLAT.

### Нейтронная звезда — особые условия

- НЗ не определяется массой — это наследуемый тип, возникающий при сверхновой синего гиганта
- Рассыпается при mass ≥ 1001 у.е. — в `processStarLifecycle` и в `resolveCollision`
- Счётчики смерти: `nsDiedCool` / `nsDiedHeat` / `nsDiedMass` / поглощение ЧД

## 10. ЧЁРНЫЕ ДЫРЫ

- Поглощают **любой объект полностью**: `bh.mass += other.mass`. Остатка нет.
- ЧД + ЧД → слияние в одну ЧД, бо́льшая поглощает меньшую
- **Верхнего предела массы нет**
- Дрейф наружу отключён — подчиняются orbital drag как обычные объекты

### Потеря массы ЧД

Каждый тик:
```
radiated = ceil(BH_MASS_LOSS + mass × BH_LOSS_PCT)    // 10 + 10% массы за тик
bh.mass -= radiated
```

### Нагрев соседних звёзд от ЧД

Нагрев убывает **линейно** с расстоянием. Каждая звезда в радиусе BH_RAD_RADIUS получает свой индивидуальный нагрев:

```
d = расстояние от ЧД до звезды
boost = BH_HEAT_MAX × (1 − d / BH_RAD_RADIUS)
star.temp += boost
```

- `BH_RAD_RADIUS = 10 у.е.`
- `BH_HEAT_MAX = 0.14 T/тик` — максимум вплотную к ЧД
- На краю радиуса нагрев = 0
- Нагрев **независим** от числа объектов рядом — каждая звезда получает своё boost по своей дистанции
- 0.14 T/тик ≤ |dT| красного карлика (0.14) — ЧД **не спасает ни одну звезду** от остывания

### Испарение ЧД

При `bh.mass ≤ 0` ЧД исчезает. Испускает туманности суммарной массой ~8 у.е. (через ejectSixty). Масса возвращается в систему.

### Выбор ЧД или НЗ при сверхновой синего гиганта

Детерминированно по числу ЧД в галактике в момент взрыва:

Детерминированно по счётчику сверхновых (CNT.supernovae), соотношение 1 ЧД на 2 НЗ:

| supernovae % 3 | Результат |
|---|---|
| 0 | Чёрная дыра |
| 1 | Нейтронная звезда |
| 2 | Нейтронная звезда |

Порядок: НЗ → НЗ → ЧД → НЗ → НЗ → ЧД → ...

Это гарантирует что НЗ рождаются вдвое чаще ЧД, независимо от текущего состава галактики.

## 11. НЕЙТРОННАЯ ЗВЕЗДА

Нейтронная звезда — редкий тип, возникающий исключительно при сверхновой синего гиганта, когда число ЧД в галактике превышает 40.

- Стартовая температура: 500
- dT/тик: −0.34 (остывает быстрее красного карлика)
- Рассыпается при mass ≥ 1001 у.е. → правило 60/40, режим `explode`, остаток `ejecta`

## 12. ФОРМАЦИИ (ЗВЁЗДНЫЕ ЯСЛИ)

Формация — обязательная промежуточная стадия между облаком и звездой. Масса ≥ 31 у.е., верхнего предела нет.

### Начальная скорость формации

Зависит от способа создания:

| Способ | Начальная скорость |
|---|---|
| Слияние двух звёзд (60%) | V_FLAT в центре масс пары |
| Остаток взрыва/остывания (40%) | V_FLAT (режим explode) или скорость родителя (decay) |
| Осколок разлёта через `ejectSixty` (60%) | Ближний: 1–2 у.е./тик; дальний (та же ось): 2–3 у.е./тик — абсолютные значения, не зависят от IMPULSE_MIN |
| Смена типа облака при поглощении | V_FLAT |

**Осколки 60% (`ejectSixty`) намеренно получают скорость разлёта, а не V_FLAT.** Orbital drag выравнивает орбиту после того как спадает `debris`-флаг (5 тиков). Немедленная подмена на V_FLAT создавала артефакт — правильный круг из формаций сразу после взрыва.

### Детерминированный псевдорандом разлёта (`ejectRng`)

Смещение и импульс каждого осколка псевдослучайны, но детерминированы — одинаковый тик и позиция взрыва всегда дают одинаковый узор (важно для Jump to Tick).

**Алгоритм:** LCG с константами Numerical Recipes (`1664525 × s + 1013904223`).

**Сид:** `(tick × 73856093) XOR (round(x) × 19349663) XOR (round(y) × 83492791)` — взрывы в разных точках одного тика дают разные узоры.

**Параметры на каждое направление (2 осколка):**
```
// Ближний осколок
r1   = 0.5 + rng() × 0.5    // смещение: 0.5–1.0 у.е.
imp1 = 1.0 + rng() × 1.0    // скорость: 1–2 у.е./тик

// Дальний осколок (та же ось, тот же угол)
r2   = 1.1 + rng() × 0.4    // смещение: 1.1–1.5 у.е.
imp2 = 2.0 + rng() × 1.0    // скорость: 2–3 у.е./тик
```

Масса одного осколка = `mass60 / 24`. Скорости — абсолютные, не зависят от IMPULSE_MIN.

Результат: двухслойное кольцо осколков — ближний пояс (медленный) и дальний пояс (быстрый) по каждому из 12 направлений.

### Рождение звезды из формации

Через `FORMATION_TICKS (6)` тиков после создания:

1. Если `mass < 51` — продлевает таймер на FORMATION_TICKS, ждёт следующего цикла (радиусная аккреция отключена — масса набирается только через прямые столкновения)
2. Если `mass ≥ 51` — рождает звезду (пункт 4 ниже)
3. Если `mass ≥ 1001` — немедленный 60/40 распад
4. Если `mass ≥ 51` — рождает звезду

**Аккреция формации:** только через прямые столкновения (`resolveCollision`, 0.9 у.е.) — формация не «охотится» за объектами в радиусе. Астероиды поглощаются мгновенно (100%) при касании.

**Тип рождаемой звезды (по массе):**

| Масса формации | Рождаемый тип |
|---|---|
| 51–300 | Красный карлик |
| 301–600 | Жёлтый карлик |
| 601–1000 | Синий гигант |

**Белый карлик из формации родиться не может.** Белые карлики возникают только при остывании звезды (T ≤ 10) с массой остатка 10–15.

Рождённая звезда получает скорость V_FLAT:
```
vx = -rotDir × V_FLAT × sin(theta)
vy =  rotDir × V_FLAT × cos(theta)
```

Счётчик `bornFromFormation` растёт при каждом рождении.

## 13. ВОЗВРАТ МАССЫ

### Принцип сохранения массы

`targetMass` фиксируется при загрузке галактики как суммарная масса всех объектов. Каждый тик:

```
deficit = targetMass - currentMass
```

Дефицит компенсируется влётом новых объектов с периметра. Масса в системе не теряется — циклически возвращается.

### Точки влёта

800 точек по периметру квадрата `FIELD_SIZE × FIELD_SIZE`, перемешанных алгоритмом Fisher-Yates с LCG-генератором от сида галактики. Распределение: по 200 точек на каждую из 4 сторон квадрата. Обход цикличный и детерминированный: `inflowPoints[inflowIdx % 800]`.

### Скорость и тип влетающих объектов

```
theta = atan2(pos.y - CENTER, pos.x - CENTER)
vx = -cos(theta) × 4.0    // чисто радиально к центру, высокая скорость
vy = -sin(theta) × 4.0
```

- Тип: если `actual ≤ NEB_RETURN_MAX (5)` → туманность, иначе → астероид (до `AST_RETURN_MAX (30)`)
- Все влетающие объекты: `debris = true`, `debris_ticks = 10`
- Orbital drag и radial drag постепенно конвертируют радиальную скорость в тангенциальную и гасят радиальный дрейф

## 15. ВИЗУАЛИЗАЦИЯ

### Canvas и управление

- Canvas адаптивный (resize по окну браузера)
- **Зум:** колесо мыши (30%–2000%). Сохраняет точку под курсором — зум "под мышь"
- **Панорамирование:** перетаскивание мышью
- **Граница галактики:** тонкая синяя окружность r = GALAXY_R
- **Зона хаоса:** фиолетовое кольцо r = CHAOS_R
- **Центр:** фиолетовая точка

### Хвосты траекторий

Каждый объект хранит 3 предыдущих позиции: `prevX/Y`, `prevX2/Y2`, `prevX3/Y3`.

- **Обычный хвост** (всегда): линия от `prevX/Y` к текущей позиции, прозрачность 18%, толщина 0.8px
- **Расширенный хвост** (при наведении): 3 сегмента с затуханием 35% / 20% / 18%, толщина 1.3 и 1.0px

### Визуальные эффекты

- **Unstable:** пульсирующий оранжевый ореол. `pulse = 0.4 + 0.4 × sin(time / 150)`
- **Формация:** оранжевое свечение радиальным градиентом в радиусе 4×r
- **Glow:** радиальный градиент 2.8×r с alpha×0.25, если `alpha > 0.5`
- **BH кольцо:** окружность r×2.2, `stroke rgba(187,68,255,0.18)`
- **НЗ точка:** белая точка r×0.35 внутри объекта

### Координатная сетка

Шаг 5 у.е., подписи каждые 20 у.е. Переключается кнопкой GRID.

### Тултип при наведении

Ближайший объект в радиусе 14px. Показывает: тип, MASS, T, AGE, R, vx, vy, |v|.

## 18. ЭКСПОРТ СНАПШОТА

Кнопка Export скачивает `snapshot_tick_N.json` со структурой:

- `tick` — номер текущего тика
- `rotation_dir` — направление вращения галактики (+1 или -1)
- `target_mass` — целевая масса системы (фиксируется при генерации)
- `return_pool` — масса в пуле возврата
- `counters` — все CNT поля: collisions, deaths, evolution, lifespan и т.д.
- `objects` — массив объектов с полями: id, type, star_type, x, y, r, theta, mass, vx, vy, omega, temp, age, debris
