# Сервер УРОБОРОС

Go-сервер: единое игровое время, авторитетная симуляция сектора и раздача клиента (`../client`).

## Запуск

```
cd server
go run .
```

Или собрать один исполняемый файл:

```
cd server
go build -o ouroboros-server.exe .
.\ouroboros-server.exe
```

При старте печатает адреса, включая тот, по которому сервер виден с телефона.

### Ключи

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `-port` | `8080` | порт HTTP |
| `-speed` | `0.25` | стартовое ускорение: игровых месяцев за реальную секунду |
| `-seed` | `0` | сид генерации галактики; `0` — случайный при запуске |

Один и тот же `-seed` даёт побитово одинаковую галактику — удобно, когда нужно
воспроизвести ситуацию.

## Тест с телефона

1. Телефон и компьютер — в одной сети (один Wi-Fi).
2. Запустить сервер и взять адрес из строки «с телефона» — например `http://192.168.1.106:8080/`.
3. Открыть этот адрес в браузере телефона.

Если страница не открывается, почти всегда дело в брандмауэре Windows. Разрешить
порт (PowerShell **от администратора**, один раз):

```
netsh advfirewall firewall add rule name="Ouroboros 8080" dir=in action=allow protocol=TCP localport=8080
```

Убрать правило, когда больше не нужно:

```
netsh advfirewall firewall delete rule name="Ouroboros 8080"
```

Прочие причины, если правило есть, а не работает: телефон в гостевой сети или
включена изоляция клиентов на роутере; в сети другой адрес интерфейса (сервер
печатает все найденные — попробовать по очереди).

## Время

Сервер — единственный источник игрового времени. Клиент собственных часов не
ведёт: он берёт время сервера и между синхронизациями лишь экстраполирует его.

Ускорение для тестов меняет **только** множитель: сколько игровых месяцев
проходит за реальную секунду. Способ счёта не меняется — за секунду просто
происходит больше. Поэтому прогон на `speed=20` и на `speed=0.25` даёт
одинаковую картину на одном и том же игровом времени.

Время монотонно и не сбрасывается при смене скорости и на паузе (`speed=0`).
Накопление идёт по фактически прошедшему реальному времени
(`months += speed × Δt`), поэтому дрожание таймера ОС не копится в ошибку —
замер на 4 секундах даёт отклонение 0,006%.

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/time` | `{months, speed, ticks, uptime, stampMs, seed, seq}` |
| GET | `/api/galaxy` | то же + `objects[]` — полный состав сектора |
| GET | `/api/stats` | сводка: количество по типам, суммарная масса, счётчики |
| GET | `/api/events?since=N` | SSE-поток: время, скорость и события состава |
| POST | `/api/speed` | `{"speed": <мес/сек>}` — ускорение; действует для всех клиентов |

Скорость ограничена сверху `maxSpeed = 240` мес/сек (предохранитель от опечатки
в запросе); отрицательные значения приводятся к нулю.

### Как клиент держит состав в актуальном состоянии

Позиция объекта — чистая функция игрового времени:

```
x(t) = x0 + arc · (t − t0)
```

`x0`, `t0`, `arc` приходят с сервера и не меняются, пока объект жив. Поэтому
поток не передаёт координаты: клиент один раз забирает состав через
`/api/galaxy`, дальше применяет события `spawn` / `despawn` и рисует положение
на любой момент времени сам. Частота кадров и уход вкладки в фон на картинку не
влияют — вернувшись, она сразу оказывается там, где надо.

Если клиент отстал больше, чем сервер хранит в буфере событий (4096 событий —
достижимо на сильном ускорении), сервер присылает `resync`, и клиент
перезабирает состав целиком. Ответы сжимаются gzip: 230 КБ → 78 КБ.

## Устройство

| Файл | Что внутри |
|---|---|
| `main.go` | HTTP, эндпоинты, SSE, определение адреса в локальной сети |
| `clock.go` | единые часы: накопление игрового времени, ускорение, пауза |
| `galaxy.go` | генератор: зоны, рукава, массы, кривая скорости по орбитам |
| `planets.go` | заселение звёзд планетами и распространение ресурсов |
| `sim.go` | жизненный цикл: очередь выходов, оборот объектов, события |
| `gzip.go` | сжатие ответов (кроме SSE — его нельзя буферизовать) |

Правила генерации перенесены из прежнего клиентского прототипа без изменений и
соответствуют ТЗ.md §2.1–2.3, §2.11. Состав сектора при одинаковом сиде
совпадает с прежним клиентским: 504 объекта — 101 звезда, 149 туманностей,
246 астероидных полей, 8 чёрных дыр, из них 4 стабильных мира.
