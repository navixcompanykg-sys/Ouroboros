# ТЗ: Склад (Warehouse)

Единый документ по механике складской системы игры.

---

## 1. Общая концепция

У каждого игрока на каждой планете — **свой личный склад**. Склады разных игроков на одной планете физически независимы, но могут взаимодействовать через аренду и торговлю.

Склад является **центральным узлом экономики** планеты: через него проходят все добытые ресурсы, произведённые компоненты и входящие поставки.

## 4. Если своего склада нет

Если у игрока **нет склада** на данной планете (или его ёмкость исчерпана), ресурсы автоматически отгружаются на **чужой склад** по следующему приоритету:

### 4.1 Алгоритм выбора склада

1. Найти все склады на планете с **свободным арендным местом**
2. Отсортировать по **цене аренды** (по возрастанию)
3. Среди складов с одинаковой ценой — выбрать **наиболее свободный** (больше % свободного места)
4. Если ни одного склада нет или все заняты — ресурсы **теряются** (сбрасываются в космос / уничтожаются)

> Игрок получает уведомление если его ресурсы некуда отгружать.

## 5. Аренда

### 5.1 Настройки арендодателя

Владелец склада устанавливает:

| Параметр | Описание | По умолчанию |
|---|---|---|
| **Доля под аренду** | % от общей ёмкости, доступный арендаторам | 0% |
| **Ставка аренды** | Токенов за каждые 100 у.м. в тик | 0 ₮ |

Пример: склад 5 000 у.м., 30% под аренду = **1 500 у.м.** доступно арендаторам.  
Ставка 5 ₮ → арендатор, занявший 300 у.м., платит **15 ₮ в тик**.

### 5.2 Долг и арест имущества

Если арендатор не оплачивает аренду (нет токенов на счету):

1. **Долг накапливается** каждый тик
2. Имущество арендатора **арестовывается** (он не может забрать ресурсы)
3. Если **долг ≥ рыночной стоимости** арестованных ресурсов — ресурсы переходят в собственность владельца склада
4. Рыночная стоимость оценивается по **галактической средней цене** на момент ареста

> Арендатор видит статус «⚠️ ДОЛГ» в интерфейсе своего склада на этой планете.

## 6. Торговля ресурсами

### 6.1 Продажа (ордера на продажу)

Для каждого ресурса на складе игрок может установить:

| Параметр | Описание |
|---|---|
| **Цена продажи** | Токенов за единицу (0 = не продаётся) |
| **Неприкосновенный запас** | Минимальное кол-во единиц, которое нельзя продать |

Если `остаток ≤ неприкосновенный запас` — продажи останавливаются автоматически.

### 6.2 Динамическое снижение цены (демпинг при переполненности)

Позволяет автоматически снижать цену при накоплении излишков.

**Настройки на ресурс:**

| Параметр | Описание | По умолчанию |
|---|---|---|
| **Норма запаса** | Целевой уровень хранения (ед.) | 20 |
| **Шаг снижения** | % снижения цены за каждые 10% сверх нормы | — |
| **Минимальная цена** | Цена не опускается ниже этого значения | — |

**Формула:**

```
Превышение = (текущий запас − норма запаса) / норма запаса × 100%
Шагов = floor(Превышение / 10)
Цена = max(мин. цена, базовая цена × (1 − шаг/100) ^ Шагов)
```

**Пример:**

| Параметр | Значение |
|---|---|
| Базовая цена продажи | 50 ₮ |
| Норма запаса | 20 ед. |
| Шаг снижения | 10% за каждые 10% превышения |
| Минимальная цена | 20 ₮ |

| Запас | Превышение | Шагов | Итоговая цена |
|---|---|---|---|
| 20 ед. | 0% | 0 | 50 ₮ |
| 22 ед. | 10% | 1 | 45 ₮ |
| 24 ед. | 20% | 2 | 40.5 ₮ |
| 30 ед. | 50% | 5 | 29.5 ₮ |
| 40 ед. | 100% | 10 | 20 ₮ (min) |

### 6.3 Покупка (ордера на покупку)

Для каждого ресурса игрок устанавливает:

| Параметр | Описание |
|---|---|
| **Базовая цена покупки** | Токенов за единицу, которую игрок готов платить |
| **Целевой запас** | До какого уровня докупать ресурс |
| **Надбавка при дефиците** | % доплата если запас < 50% от нормы |

**Пример надбавки при дефиците:**

| Параметр | Значение |
|---|---|
| Базовая цена покупки | 40 ₮ |
| Норма запаса | 100 ед. |
| Надбавка при дефиците | +30% |

Если запас упал ниже 50 ед. (< 50% нормы) → цена покупки автоматически растёт до **52 ₮** (+30%).  
Это позволяет перехватить ресурс у конкурентов в критической ситуации.

#### Карточка флота

Квадратная иконка для каждого флота на орбите/планете:

| Элемент | Описание |
|---|---|
| Иконка | 🚀 (тип корабля или флага игрока) |

| Заполненность | `занято / всего у.м.` |
| Статус | `ПОЛНЫЙ` / `N у.м. своб.` |
| Цвет рамки | Зелёный — свой флот, серый — чужой (только если разрешена загрузка) |

Чужие флоты видны, но перегрузка в них возможна только если владелец флота дал разрешение (настройка на стороне флота).

#### Логика операции

**Склад → Трюм (выгрузка со склада):**
1. Игрок выбирает флот
2. Для каждого ресурса вводит количество
3. Система проверяет: `кол-во × масса_ед ≤ свободно в трюме`
4. Система проверяет: `кол-во ≤ остаток на складе − неприкосновенный запас`
5. При подтверждении — ресурсы списываются со склада и добавляются в трюм мгновенно

**Трюм → Склад (загрузка на склад):**
1. Игрок выбирает флот (только свой или с разрешением)
2. Выбирает ресурсы и количество из трюма
3. Система проверяет: `кол-во × масса_ед ≤ свободно на складе`
4. Кнопка **[Выгрузить всё из трюма на склад]** — один клик выгружает весь груз флота на склад (если есть место)

#### Ограничения

| Ситуация | Поведение |
|---|---|
| Трюм флота полон | Поле ввода неактивно, показано «ПОЛНЫЙ» |
| Склад полон | Нельзя загрузить из трюма, показано предупреждение |
| Ресурс ≤ неприкосновенного запаса | Поле ввода ограничено сверху |
| Флот улетает в этот тик | Предупреждение «Флот отправится в этом тике» |
| Чужой флот без разрешения | Карточка затемнена, клик недоступен |

## 10. Архитектура хранения данных

### 10.1 Принцип хранения

Следует общему правилу игры (из OUROBOROS_design.md):

> **В памяти** — единственный источник истины во время работы сервера.  
> **На диске** — только чекпоинты и сохранение при остановке.

Склады не хранятся в `star_registry.json` и `galaxy.json` — это данные симуляции, а не состояния игроков. Для хранения игрового состояния вводится отдельный файл.

### 10.2 Файловая структура

```
server/
  game_state.json        ← Полный чекпоинт игрового состояния
  star_registry.json     ← Реестр звёзд (только астрофизика, без экономики)
  galaxy.json            ← Симуляция галактики (без изменений)
```

`game_state.json` пишется на диск:
- При каждом N-м тике (интервал настраивается в `config.json`, по умолчанию каждые 10 тиков)
- При штатной остановке сервера
- При команде `/checkpoint` (ручное сохранение)

### 10.3 Схема данных (Go-структуры)

```go
// Количество ресурса на складе
type ResourceMap map[string]float64  // resource_id → количество единиц

// Настройки торговли по одному ресурсу
type ResourceSettings struct {
    SellPrice  float64 `json:"sell_price"`   // ₮/ед., 0 = не продаётся
    Reserve    float64 `json:"reserve"`      // неприкосновенный запас, ед.
    Norm       float64 `json:"norm"`         // целевой запас, ед. (дефолт 20)
    DumpStep   float64 `json:"dump_step"`    // % снижения цены за каждые 10% превышения нормы
    MinPrice   float64 `json:"min_price"`    // мин. цена продажи, ₮
    BuyPrice   float64 `json:"buy_price"`    // цена покупки, ₮/ед.
    BuyTarget  float64 `json:"buy_target"`   // целевой запас для закупки, ед.
    BuyPremium float64 `json:"buy_premium"`  // надбавка % если запас < 50% нормы
}

// Данные одного арендатора на чужом складе
type TenantData struct {
    Resources ResourceMap `json:"resources"`
    Debt      float64     `json:"debt"`      // накопленный долг, ₮
    Arrested  bool        `json:"arrested"`  // имущество арестовано
}

// Состояние одного склада (один игрок, одна планета)
type WarehouseState struct {
    BuildingLevel int                         `json:"building_level"` // 0 = нет здания
    Resources     ResourceMap                 `json:"resources"`      // ресурсы владельца
    Settings      map[string]ResourceSettings `json:"settings"`       // настройки по ресурсу
    RentalPct     float64                     `json:"rental_pct"`     // % под аренду
    RentalRate    float64                     `json:"rental_rate"`    // ₮ / 100 у.м. / тик
    Tenants       map[string]TenantData       `json:"tenants"`        // player_id → данные
}

// Все склады одного владельца (игрок или AI)
type OwnerWarehouseData struct {
    OwnerID   string                     `json:"owner_id"`
    OwnerType string                     `json:"owner_type"` // "player" | "ai"
    Warehouses map[string]WarehouseState `json:"warehouses"` // planet_key → склад
}

// Верхний уровень — всё игровое состояние
type GameState struct {
    Tick       int64                         `json:"tick"`
    Warehouses map[string]OwnerWarehouseData `json:"warehouses"` // owner_id → данные
    // ...флоты, политика, и т.д. в будущем
}
```

### 10.4 Ключ планеты

Склад идентифицируется строкой:

```
planet_key = "{star_id}:{orbit_index}"
```

Пример: `"star_0042:3"` — четвёртая планета звезды 42.

Этот ключ используется везде: в карте складов, в событиях гибели звезды, в логах.

### 10.5 AI-склады

AI-игроки используют **идентичную структуру** `OwnerWarehouseData` с `owner_type: "ai"`.

Отличия только в поведении:
- Настройки торговли и аренды выставляются автоматически по стратегии AI
- Долги AI не накапливаются (AI платит всегда если есть ресурсы)
- При банкротстве AI — его склады переходят в «заброшенные» (новая категория, доступна для захвата)

### 10.6 In-memory карта

Во время работы сервера `GameState` живёт целиком в памяти:

```go
var globalGameState *GameState   // инициализируется при старте из game_state.json
var gameStateMu sync.RWMutex    // RW-мьютекс для конкурентного доступа
```

Тик-процессор (`tickLoop`) держит write-lock на время обработки тика.  
HTTP-запросы (чтение UI) используют read-lock.

### 10.7 Гибель звезды — каскадное стирание

#### Предсказуемость

Температура звезды убывает по известной формуле. Момент смерти (`temp ≤ 10`) вычисляется заранее и известен серверу и клиентам.

#### Этапы каскада

```
Тик смерти − 50    →  Глобальное оповещение: «Звезда {name} угасает. Осталось ~50 тиков»
Тик смерти − 20    →  Личное уведомление всем владельцам складов в системе
Тик смерти − 5     →  Красное предупреждение: «Срочная эвакуация. 5 тиков»
Тик смерти − 0     →  Каскадное стирание
```

#### Алгоритм стирания (Тик 0)

```
for each planet_key where planet_key starts with "{dead_star_id}:":
    for each owner_id in GameState.Warehouses:
        wh = GameState.Warehouses[owner_id].Warehouses[planet_key]
        if wh exists:
            // Уведомить владельца о потере
            notify(owner_id, "ПОТЕРЯ: склад на {planet_key} уничтожен")
            // Уведомить арендаторов о потере их ресурсов
            for each tenant_id in wh.Tenants:
                notify(tenant_id, "ПОТЕРЯ: ресурсы на складе {planet_key} уничтожены")
            // Удалить склад
            delete(GameState.Warehouses[owner_id].Warehouses, planet_key)
        // Если склад пустой — пропустить
```

Ресурсы, **эвакуированные в трюм флота до тика смерти**, сохраняются — флот физически покидает систему и уходит в космос.

#### Что стирается

| Объект | Судьба при гибели звезды |
|---|---|
| Ресурсы на складах | ❌ Уничтожены безвозвратно |
| Ресурсы арендаторов | ❌ Уничтожены (долги аннулируются) |
| Настройки складов | ❌ Уничтожены |
| Здания на планетах | ❌ Уничтожены |
| Ресурсы в трюмах флотов | ✅ Сохраняются (если флот улетел) |
| Флоты на орбите в момент Т0 | ⚠️ Уничтожаются (не успели улететь) |
| Запись в star_registry.json | ✅ Остаётся (историческая запись) |

#### Окно эвакуации флота

Флот успевает улететь если **отдан приказ на вылет до тика смерти включительно**. Флот, находящийся на орбите в момент `temp = 10`, уничтожается вместе с планетой.

### 10.8 Чекпоинт и восстановление

**Запись:**
```go
func saveCheckpoint() {
    gameStateMu.RLock()
    defer gameStateMu.RUnlock()
    data, _ := json.MarshalIndent(globalGameState, "", "  ")
    os.WriteFile("game_state.json", data, 0644)
}
```

**Чтение при старте:**
```go
func loadGameState() {
    data, err := os.ReadFile("game_state.json")
    if err != nil {
        // Первый запуск — создать пустое состояние
        globalGameState = &GameState{Warehouses: make(map[string]OwnerWarehouseData)}
        return
    }
    json.Unmarshal(data, &globalGameState)
}
```

**Целостность:** если `game_state.json` повреждён — сервер стартует с пустым состоянием и пишет об этом в лог. Данные симуляции (галактика, звёзды) не затрагиваются.

### 10.9 API эндпоинты (планируемые)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/warehouse/{planet_key}` | Получить свой склад на планете |
| `POST` | `/warehouse/{planet_key}/settings` | Обновить настройки склада |
| `POST` | `/warehouse/{planet_key}/transfer` | Перегрузить ресурсы (склад ↔ флот) |
| `GET` | `/warehouse/{planet_key}/market` | Публичные данные склада (аренда, цены) |
| `POST` | `/checkpoint` | Ручное сохранение состояния |
